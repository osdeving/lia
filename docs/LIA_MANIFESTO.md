# LIA Manifesto: O Fim do Código Artesanal

O **LIA (Linguagem Intermediária Assistida)** não é apenas um toolchain; é uma nova filosofia de construção de software para a era da Inteligência Artificial Genérica.

## 1. O Código não é o Destino

No desenvolvimento tradicional, o código-fonte humano é o artefato final e a "fonte da verdade". No LIA, o código é um efeito colateral de uma **Intenção Semântica** verificada.

## 2. Model-First, não Human-First

As linguagens de programação atuais foram desenhadas para serem lidas por humanos. O LIA foi desenhado para ser:

- **Gerado por Modelos**: Estruturado para minimizar alucinações.
- **Validado por Máquinas**: Determinístico e linkável.
- **Auditado por Humanos**: Reprodutível através de `prompt-tapes`.

## 3. Modularidade Atômica

Acreditamos que o software deve ser gerado em paralelo. Um agente foca no domínio, outro na infraestrutura. O **Linker LIA** tece essas peças semânticas, garantindo que as políticas de arquitetura (Clean Architecture, Hexagonal, etc.) sejam respeitadas por construção, não por vontade.

## 4. Reprodutibilidade como Direito

Se você não pode repetir a geração a partir de um input de IA, você não tem software; você tem um acidente feliz. O LIA exige que cada artefato carregue sua proveniência.

## 5. O Papel do Arquiteto

O arquiteto deixa de ser o "escritor de código master" e passa a ser o **"Designer de Políticas"**. Ele define os *constraints*, os *budgets* e as *interfaces*; a IA preenche as lacunas seguindo essas leis.
